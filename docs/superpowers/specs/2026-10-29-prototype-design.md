# 「30일 후 삭제됩니다」 첫 프로토타입 설계

작성 2026.10.29 / 기획서 v0.9 기준

## 1. 목적

두 가지를 작게 확인한다.

1. 하루 루프(슬롯 3개, 선택지 대화, 현실 과제, 숨김 수치)가 굴러가고 다음 슬롯이 기다려지는가
2. 하린이 휴대폰 화면을 뚫고 원룸으로 나오는 장면이 유니티에서 연출로 성립하는가

프로토타입은 본편 프로젝트의 시작점이다. 화면 코드는 다시 짜도 되지만, 대사 데이터 형식과 `GameState` 는 본편까지 가져간다.

## 2. 범위

넣는 것

1. 첫 장면: 노이즈 낀 화면에서 하린이 카메라를 보고 말을 건다
2. 1일차 아침, 저녁, 밤 슬롯. 1막 화면은 세로 화면 전체가 메신저 앱 "되감기"다. 위쪽 창에 3D 하린, 아래에 선택지 대화
3. 밤 슬롯의 현실 과제 하나
4. 나오는 장면: 하린의 손이 화면을 뚫고 나오고, 카메라가 폰에서 빠져 원룸이 드러난다
5. 2막 한 컷: 원룸에서 하린이 주인공 이름을 부르다 멈추고 몸이 잠깐 흐려진다
6. 개발용 화면: 날, 슬롯, 숨김 수치 4개를 보고 바꾼다

슬롯 사이 시간은 빠른 모드로 60초다. 개발용 "다음 슬롯" 버튼으로 바로 넘길 수 있다.

빼는 것: 푸시 알림, 실제 시간 진행, 결말, 외출 장소, 툰 셰이더 비교, 엔딩 카드, 2일차 이후.

## 3. 바탕

| 항목 | 값 |
|---|---|
| 엔진 | Unity 6 LTS, URP |
| 프로젝트 위치 | `unity/` (저장소 안) |
| 화면 | 세로 9:16, 기준 해상도 1080 × 1920 |
| 하린 모델 | `hari/gpt/previous/harin-v2.vrm` 을 UniVRM(VRM 1.0 패키지)으로 가져온다. 최신 얼굴 v20 은 VRM으로 내보내면 바꿔 끼운다 |
| 에디터 조작 | 유니티 공식 MCP(AI Assistant 패키지). Personal 라이선스에서 막히면 무료 커뮤니티판 MCP for Unity(Coplay)로 바꾼다 |
| 대상 기기 | 에디터 플레이 모드로 먼저 확인하고, 안드로이드 빌드는 마지막에 한 번 뽑는다 |

`unity/Library/`, `unity/Temp/`, `unity/Logs/`, `unity/obj/`, `unity/Build/`, `unity/UserSettings/` 는 `.gitignore` 에 넣는다.

## 4. 장면 구성

장면 파일은 `Prototype.unity` 하나다. 원룸 3D 공간 안에 휴대폰이 놓여 있다.

- 앱 속 무대: 원룸과 떨어진 좌표에 하린을 세우고 전용 카메라로 찍어 RenderTexture 에 담는다. 이 그림이 메신저 위쪽 창에 뜬다
- 1막: 메인 카메라가 폰 화면에 붙어 있어 메신저 UI만 보인다. UI는 폰 화면 위의 World Space 캔버스다
- 나오는 장면: Timeline 하나로 짠다. 순서는 화면 노이즈 → 폰 화면에 손이 비침 → 하린을 원룸 쪽 좌표로 옮김 → 메인 카메라가 폰에서 뒤로 빠짐 → 원룸 전체가 보임. 길이는 10초 안팎
- 원룸: 상자와 평면으로 침대, 책상, 창문 자리만 잡는다. 조명은 밤 하나

같은 하린 모델 하나를 앱 속 무대와 원룸 사이에서 옮기므로 나오는 순간에 모델이 바뀌지 않는다.

## 5. 코드 단위

| 단위 | 하는 일 | 기대는 것 |
|---|---|---|
| `ScriptData` | 대사 JSON을 읽어 장면 목록으로 만든다 | 없음 |
| `GameState` | 날, 슬롯, 숨김 수치 4개(안정도, 어긋남, 마음의 문, 남은 재생 시간)를 들고 JSON으로 저장한다 | 없음 |
| `SlotClock` | 다음 슬롯이 열릴 때까지 시간을 잰다. 빠른 모드 60초, 개발용 즉시 넘김 | `GameState` |
| `DialogueRunner` | 장면을 한 줄씩 돌리고, 선택 결과의 수치 변화를 `GameState` 에 넘기고, 다음 장면을 고른다 | `ScriptData`, `GameState` |
| `ChatView` | 말풍선, 선택지, 감정 버튼, 잠금화면 알림 흉내를 그린다 | `DialogueRunner` 의 이벤트 |
| `HarinPuppet` | VRM 표정, 눈 깜빡임, 노이즈와 흐려짐 정도를 다룬다 | UniVRM |
| `EmergenceSequence` | 나오는 장면 Timeline을 틀고 끝나면 2막 한 컷으로 넘긴다 | Timeline, `HarinPuppet` |
| `DevPanel` | 날, 슬롯, 수치를 보고 바꾼다 | `GameState`, `SlotClock` |

`ScriptData`, `GameState`, `DialogueRunner` 는 유니티 화면 없이 돌아가는 순수 C# 으로 짓는다. 본편으로 그대로 가져가기 위해서다.

## 6. 대사 데이터

파일: `unity/Assets/StreamingAssets/script/day1.json`

```json
{
  "day": 1,
  "scenes": [
    {
      "id": "d1_morning",
      "slot": "morning",
      "lines": [
        { "who": "harin", "text": "...보여? 아, 보이는구나.", "face": "surprised" },
        { "who": "harin", "text": "{player}, 맞지? 오늘부터 내가 옆에 있을게.", "face": "happy", "glitch": 0.2 }
      ],
      "choices": [
        { "text": "누구세요?", "effects": { "deviation": 1 }, "next": "d1_morning_who" },
        { "text": "앱 지울게.", "effects": { "stability": -1 }, "next": "d1_morning_delete" }
      ]
    }
  ]
}
```

| 필드 | 뜻 |
|---|---|
| `who` | `harin`, `player`, `system`(앱 안내문) 중 하나 |
| `face` | VRM 표정 이름. `neutral`, `happy`, `sad`, `angry`, `surprised`, `relaxed` |
| `glitch` | 그 줄에서 화면 노이즈 세기. 0 → 1, 없으면 0 |
| `{player}` | 주인공 이름 자리 |
| `effects` | 숨김 수치 변화. `stability`, `deviation`, `heart` |
| `next` | 다음 장면 id. 없으면 그 슬롯이 끝난다 |
| `type` | 기본은 대화. `feeling` 이면 감정 버튼 장면, `task` 면 현실 과제 장면 |

감정 버튼 장면(`feeling`)은 기획서 v0.9 7장대로 수치를 바꾸지 않는다. 고른 감정에 맞춘 반응 줄만 보여 준다.

## 7. 1일차 대사 방향

본편 1막 10일을 하루에 눌러 담는다. 장면마다 3 → 8줄로 짧게 쓴다.

| 슬롯 | 내용 | 노리는 감정 |
|---|---|---|
| 아침 | 앱 설치, 이름 입력, 노이즈 속 하린의 첫 인사 | 낯섦, 호기심 |
| 저녁 | 하린이 실연 이야기를 들어 준다. "아프지 않게 해줄게"가 처음 나오고, 운영사 목적이 한 줄 비친다. 감정 버튼 입력 한 번 | 위로, 은근한 불안 |
| 밤 | 현실 과제: 서윤 대화방 지우기 / 친구 단톡에 답하기 / 둘 다 미루기. 하린이 운영사 뜻과 어긋나는 쪽을 권한다. 끝에 "거기 따뜻해 보여" 뒤로 나오는 장면 | 어긋남의 첫 신호, 정점 |
| 2막 한 컷 | 원룸에서 하린이 주인공 이름을 부르다 멈추고 몸이 흐려진다 | 돌봄 방향이 뒤집힘 |

## 8. 저장과 오류 처리

- `GameState` 는 슬롯이 끝날 때마다 `Application.persistentDataPath/save.json` 에 저장한다
- 저장 파일이 깨졌거나 버전이 다르면 새 게임으로 시작하고 콘솔에 경고를 남긴다
- 대사 JSON에서 `next` 가 없는 장면 id를 가리키면 로드할 때 오류를 내고 어느 장면인지 밝힌다
- 장면 도중 앱을 끄면 그 슬롯 처음부터 다시 본다

## 9. 확인 방법

- EditMode 테스트(Unity Test Framework)
  - `ScriptData`: 예시 JSON을 읽어 장면 수, 선택지, effects 가 맞는지. 없는 `next` 를 잡아내는지
  - `GameState`: 수치 변화 적용, 저장 후 다시 읽기, 깨진 저장 파일 처리
  - `DialogueRunner`: 선택지를 고르면 다음 장면으로 가고 수치가 바뀌는지. `feeling` 장면이 수치를 바꾸지 않는지
- 플레이 모드 확인: MCP로 플레이 모드를 돌려 아침 → 저녁 → 밤 → 나오는 장면 → 2막 한 컷을 개발용 버튼으로 넘기며 화면을 캡처한다
- 마지막으로 안드로이드 빌드를 한 번 뽑아 실제 폰에서 30fps가 나오는지 본다

## 10. 다 됐다고 보는 기준

1. 에디터에서 첫 장면부터 2막 한 컷까지 멈춤 없이 이어진다
2. 고른 선택지에 따라 개발용 화면의 숨김 수치가 바뀐다
3. 나오는 장면에서 하린 모델이 바뀌거나 사라지지 않고 이어진다
4. EditMode 테스트가 모두 통과한다
5. 안드로이드 빌드가 실제 폰에서 실행된다
